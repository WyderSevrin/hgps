How to code :

Each change should be optimized for readability, this includes centralized methods, centralized styling, be aware of helper classes, like utils.
It's better to have readable code rathen than overoptimised code. I want to be able to read the code and be able to understands rapidly what is happening.

A good thing is to test the changes made do not break existing functionality, it is also a good thing to ask me, the prompter if there is a risk of performance,
maintainability or a if my suggestion/prompts is a bad idea and not to simply execute blindly my request.


What to look out for :

To think in advance, this project will be deployed on a platform like aws or azure. So try to structure the code in a way that deployment will be simple. For example
the config should be separated for dev and prod environment.

In the DESCRIPTION.md file you will find more explanation about the project and a TODO list, don't implement the TODO list until a say it, but keep in your mind, this way you create 
modular code which will make newer implementation easier.


Context about the Project :

The context of this project is to creat a tool to help prospector into mapping and visualizing their prospecting research. Also to help beginners to learn and understand
the hobby of gold prospecting.
